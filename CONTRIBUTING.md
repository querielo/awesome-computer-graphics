# Contributing

Thanks for considering a contribution.

If this repository helped you, please star it. If you want to send improvements, please fork it and open a pull request.

Contributions are welcome from:

- people curating useful graphics resources
- researchers, students, and practitioners fixing stale links or outdated event data
- AI coding agents helping with small, verified, high-signal updates

## What To Contribute

Useful contributions include:

- new books, courses, tools, sites, blogs, or awesome lists related to computer graphics
- event date and location updates from official sources
- broken link fixes
- typo, formatting, and clarity fixes
- short missing descriptions for existing entries

Please avoid:

- off-topic resources
- low-quality link dumps with no context
- promotional links with little educational or practical value
- large formatting-only rewrites with no content improvement

## Contribution Guidelines

Keep changes focused and easy to review.

- Prefer official websites over mirrors, reposts, or aggregator pages.
- Keep descriptions short, concrete, and useful.
- Match the existing Markdown style of the README.
- For events, prefer confirmed dates and venues from official event pages.
- If an event has not announced final details, keep it marked as TBD instead of guessing.
- Do not reorder large sections unless there is a clear reason.
- Do not add unrelated cleanup in the same pull request.

## Guidance For AI Agents

AI-assisted contributions are welcome, but they should be held to the same quality bar.

- Read the existing README structure before editing.
- Make the smallest diff that solves the problem.
- Verify links, dates, and locations against official sources when possible.
- Preserve the repository's tone and formatting.
- Do not invent metadata, dates, or descriptions.
- Do not mass-rewrite the document just because you can.
- If some information cannot be verified, leave it unchanged or clearly marked as TBD.

## How To Submit

1. Star the repository if you find it useful.
2. Fork the repository.
3. Create a focused branch for your change.
4. Update the relevant section in the README.
5. Open a pull request with a short explanation of what changed and how you verified it.

Helpful pull request examples:

- add new WebGPU learning resources
- update 2026 conference schedule entries
- fix broken links in tools section

## Suggested Checklist

Before opening a pull request, check that:

- every added link works
- the resource is relevant to computer graphics
- the description is concise
- the formatting matches nearby entries
- the change is scoped to one topic when possible

Small, accurate contributions are excellent. If you are not sure whether something belongs here, open a pull request anyway and explain your reasoning.
